## 1. Что даёт бэкенд (сводка эндпоинтов)

Полный контракт — `03-api-contract.md` §4; ниже — рабочая сводка для планирования.

| Endpoint | Доступ | Суть |
|---|---|---|
| `GET /muscle-groups`, `GET /equipments` | публичный | справочники строк для фильтров и тел запросов |
| `GET /exercises` | опциональная авторизация | список: `type` (обязателен: `basic`/`public`/`own`/`all`), `muscle_group` (несколько), `equipment` (несколько), `search`, `limit` (обязателен, 1…1000), `offset` (обязателен, 0…100000); ответ — голый массив `Exercise` без `total`; сортировка по названию; без токена — базовые и публичные |
| `GET /exercises/{id}` | приватный | упражнение по id; `403` на чужое (включая публичные чужие — они доступны только через список) |
| `POST /exercises` | приватный | создание своего: `name`, `is_public` (по умолчанию `false`), `description`?, `muscle_groups`, `equipment` |
| `PATCH /exercises/{id}` | приватный | частичное обновление своего; `id` в теле = пути; `403` на чужое и на любое базовое |
| `DELETE /exercises/{id}` | приватный | мягкое удаление своего, `200` без тела |

Поля упражнения в ответе: `id`, `name`, `description` (`omitempty`), `owner_id`
(`omitempty` — у базовых отсутствует), `muscle_groups`, `equipment`, `created_at`.
**`is_public` в ответе нет** (поле только в телах `POST`/`PATCH`) — состояние
публикации из объекта упражнения не читается, обходной путь — §4, U5. Схема
ответа `POST` в Swagger — дефект спецификации (`CreateExerciseRequestBody`
вместо `Exercise`); клиент парсит ответ как `Exercise`.

Ключевые ошибки: `400` (невалидный `type`/`limit`/`offset`/UUID),
`user_id_required_for_filter` (`400` — свой набор без токена), `invalid_token` /
`token_expired` (`401` — уже покрыто single-flight refresh из `AsAuth_Session`),
`403` (не ваше), `404` (не найдено). `409` API не использует.

Следствия для клиента:

1. **Пагинация обязательна и без `total`:** конец списка определяется по длине
   страницы (меньше `limit` — данных больше нет). Клиентская страница — 50.
   Минимумы по Swagger: `limit` ≥ 1, `offset` ≥ 0.
2. **«Свои» приходит только с токеном:** `type=own`/`all` без токена даёт
   `user_id_required_for_filter`.
3. **Детальная карточка — только для своих:** чужое публичное упражнение имеет
   только представление в списке (вопрос к backend добавлен в §6).
4. **Справочники не версионируются** — кэш обновляется при каждом успешном
   запросе, но фолбэк на сохранённый разрешён.

## 2. Стратегия

Наследуются три правила из `06-sprint-plan.md` §1: сначала C++, потом UI;
экран не готов без аудита вёрстки (`--diag`, `problems=0` на 360/390/480,
framed, тёмная); срез не готов без теста.

Экраны фичи идут **сразу на реальном API** (как срез W, без mock-этапа):
HTTP-слой (`Http_Client`), ключи ошибок (`AApi_Error`), токены и refresh уже
живые после срезов V и W. Существующий `ExercisesPage.qml` работает на
mock-синглтоне `ExercisesViewModel` — он заменяется в U4, контракт ролей
(`qml/Mock/MockCatalog.qml`) сохраняется, делегаты не переписываются.
«Свои» упражнения хранятся и в локальном кэше — каталог остаётся читаемым
офлайн (фолбэк с маркером `from_cache`, как у профиля).

## 4. Спринты

### U1 — HTTP-слой упражнений и справочники

**Цель:** клиент умеет запрашивать списки упражнений и справочники.

| Часть | Содержание |
|---|---|
| C++ | `AExercises_Api` (`src/Data/Exercises/`): `Load_List(type, muscle_groups, equipments, search, limit, offset)`, `Load_Muscle_Groups()`, `Load_Equipments()`; сборка query-параметров со списочными значениями; ключи ошибок `user_id_required_for_filter` и списочные `400` в `AApi_Error` |
| Тесты | `tst_Exercises_Api` на `Test_Http_Server`: `type` обязателен; `limit`/`offset` всегда передаются; фильтры-списки кодируются повторением параметра; `401`-ответы проходят через сценарий 4 (refresh и повтор) |

**Готово, когда:** запрос `type=all` с токеном возвращает объединённый набор,
а без токена — базовые и публичные; ошибки API читаются через `AApi_Error`.

### U2 — Кэш и офлайн-фолбэк

**Цель:** каталог открывается без сети и не теряет свои упражнения.

| Часть | Содержание |
|---|---|
| Схема | миграция v6 → v7: `exercises_cache` (`id`, `name`, `description`, `owner_id`, `is_own`, `muscle_groups`, `equipment`, `updated_at`), `muscle_groups_ref`, `equipments_ref` |
| C++ | `AExercises_Repository`: сеть → upsert кэша → выдача; офлайн-фолбэк с маркером `from_cache`; мягкое удаление своего в кэше; справочники обновляются при каждом успехе, фолбэк — на сохранённые |
| Тесты | `tst_Exercises_Repository`: upsert не дублирует, «свои» не теряются при обновлении базовых, фолбэк отдаёт кэш с маркером, удалённое не возвращается из списков |

**Риск:** смешанный набор `type=all` при офлайне собирается из кэша —
согласованность с сервером восстанавливается при первом успешном запросе;
иначе не решить без серверного «изменено после» — принято как ограничение v1.

### U3 — ViewModel каталога

**Цель:** поиск, фильтры и пагинация инкапсулированы, UI не зависит от источника.

| Часть | Содержание |
|---|---|
| C++ | `Avm_Exercises` (`src/Presentation/`): набор (`basic` для каталога, `all` для выбора в день программы), поиск с debounce 300 мс → серверный `search`, multi-фильтры групп мышц и инвентаря, страницы по 50 «загрузить ещё» (конец — по короткой странице), роли строк под `CatalogExerciseRow` (`title`, `subtitle` из групп мышц и инвентаря) |
| Тесты | `tst_Exercises_VM`: debounce не «залипает» на быстром вводе, повторный фильтр сбрасывает offset, короткая страница закрывает пагинацию, роли совпадают с mock-контрактом |

### U4 — Каталог на реальных данных

**Цель:** вкладка «Упражнения» перестаёт быть mock-экраном.

| Часть | Содержание |
|---|---|
| UI | `ExercisesPage` на `Avm_Exercises`: поиск в строке, chips групп мышц (multi), бесконечная прокрутка, состояния: загрузка, пусто, офлайн-кэш (плашка «показан сохранённый каталог»), ошибка с повтором; `ExercisesViewModel.qml` (mock) удаляется |
| Тесты | smoke `exercises` × 5 (360/390/480, framed, dark) — `problems=0`; `tst_qml_object_smoke` без ссылок на mock |

**Готово, когда:** поиск по «жим» на живом API отдаёт серверный результат,
офлайн — кэш с плашкой, а «Ничего не найдено» — только когда сервер ответил
пустой страницей.

### U5 — Своё упражнение: создание, правка, удаление

**Цель:** кнопка «+ Своё» работает целиком, а не заглушкой `Demo.notify`.

| Часть | Содержание |
|---|---|
| C++ | `AExercises_Api`: `Create`, `Update`, `Delete` (ответ `POST` парсится как `Exercise` — схема Swagger декларирует тело запроса ошибочно); валидация: имя непустое, значения `muscle_groups`/`equipment` из справочников, `description` опционален |
| UI | состояние «Публичное» в правке инициализируется вхождением в список `type=public` (`is_public` в объекте ответа отсутствует); для нового упражнения — по умолчанию выключено |
| UI | экран формы (создание/правка): имя, описание, multi-выбор групп мышц и инвентаря (стиль `FilterChips`), переключатель «Публичное»; удаление с подтверждением; ошибки `403` («это упражнение нельзя изменить») и `400` — человеческим текстом через `AApi_Error` |
| Тесты | `tst_Exercises_Editor_VM`: создание → появляется в `type=own`, правка сохраняется, удаление убирает из списков, `403` не ломает форму |

**Готово, когда:** своё упражнение создаётся, правится, публикуется
(`is_public`), удаляется и переживает офлайн-перезапуск (кэш).

### U6 — Карточка упражнения и выбор в день программы

**Цель:** каталог связан с программой и деталями.

| Часть | Содержание |
|---|---|
| C++ | `AExercises_Api::Load_One(id)`; правило `403` чужого публичного — детальная карточка только для своих (вопрос к backend, §6) |
| UI | детальный экран упражнения (своё): описание, группы мышц, инвентарь, правка/удаление; выбор упражнения в `ProgramDayPage` из каталога (`type=all`) вместо mock-списка `exerciseOptions` — закрывает последнюю точку `Demo.notify` в дне программы |
| Тесты | `tst_Exercises_One_VM` (своё читается, чужое публичное — отказ с понятным текстом), smoke-тесты детального экрана × 5 |

## 5. Риски

1. **`403` на чужие публичные** ограничивает детальную карточку: для чужих
   публичных упражнений детального экрана не будет — предложено backend
   добавить публичное чтение по id (добавлено в §6).
2. **Поиск на кириллице:** документация обещает подстроку без учёта регистра;
   поведение на кириллице проверять живым запросом в U1 (безопасный `GET`).
3. **Справочники растут** — фильтры-чипы на 20+ значений потребуют вторую
   строку или «ещё»; решение — на аудите вёрстки U4, не заранее.
4. **Чужие публичные не кэшируются у других пользователей** — офлайн им виден
   только собственный кэш; это ожидаемо и не считается дефектом.

## 6. Запрошено у backend (дополняет `03-api-contract.md` §8)

1. Публичное чтение упражнения по id для чужих публичных (`GET /exercises/{id}`
   отдаёт `403` — детальная карточка недоступна тем, кому упражнение видно в
   списке).
2. Поле `is_public` в ответе схемы `Exercise` (сейчас состояние публикации
   недоступно клиенту — обходной путь через `type=public`).
3. Общий счётчик (`total`) или признак конца списка для `GET /exercises` —
   сейчас конец определяется по длине страницы.
4. Поведение `search` на кириллице (регистронезависимость по документации —
   проверить фактом; при расхождении — ключ ошибки или нормализация).
