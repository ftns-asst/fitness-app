# Навигация и владение данными — ревью 31.10.2026

Основание: текущие QML-экраны и их ViewModel, документация программ и дневника.
Предлагаемая структура показана в локальном интерактивном макете
`mockups-programs/10-app-navigation.html`. Папка макетов исключена из Git.

## Обнаруженные проблемы

| Место | Проблема | Решение |
|---|---|---|
| Каталог упражнений | Ответ дозагрузки заменяет модель целиком; Qt теряет положение представления | Изменять модель уведомлениями о добавленных и изменённых строках; не сбрасывать неизменённые данные |
| Обзор программы | Переходы к статистике и правилам не передают выбранную программу | Передавать идентификатор до VM; проверять принадлежность пользователю |
| Сегодня / правила программы | Два места для сегодняшних отметок | Сегодня — быстрый ввод; дневник — исправление по дате; редактор — определения правил |
| Профиль / статистика | Демонстрационная аналитика профиля конкурирует с реальными данными программы | В предложении профиль содержит настройки, реальный прогресс остаётся внутри программы |
| История | Одинаковое название у дневника и истории тренировок | Использовать «Дневник» для записей по датам; историю тренировок обозначать отдельно |
| Обзор программы | Дни выглядят кликабельными без обработчика; несколько равнозначных кнопок | Информационное расписание, сгруппированные переходы, отдельная настройка программы |
| Недоступные возможности | Запись тренировки и часть статистики упражнения ещё не реализованы | Не представлять их как работающие действия; макет не добавляет вымышленный функционал |

## Предложение структуры

Четыре постоянных назначения: **Сегодня / Дневник / Программы / Упражнения**.
Профиль доступен из шапки; его настройки остаются существующей возможностью.
Прогресс — локальное представление конкретной программы, а не ещё одна вкладка.

Дневник показывает глобальные вес и заметку за дату; рядом с правилами явно
выбрана программа. Смена программы не меняет личные записи за эту дату.
Выбор даты не сдвигает ленту; явная команда «Сегодня» может вернуть её к текущей
дате. Каталог сохраняет прокрутку при возврате из упражнения и дозагрузке.

Ввод обхватов ограничен областями, соответствующими мышцам упражнений программы.
Вес остаётся самостоятельной метрикой; исторические замеры не удаляются.
Конкретное соответствие групп мышц измеряемым областям задаётся доменным кодом,
а не отдельным списком в каждом экране.

Соответствие для формы ввода: грудь и верх спины/широчайшие — грудной обхват;
пресс/косые — талия, пресс также живот; ягодичные — ягодичный обхват;
бицепс/трицепс — плечо руки; мышцы бедра — бедро; дельты/трапеции — плечевой
пояс; икроножные — голень. Поясница и предплечья не добавляют чужой обхват,
шея автоматически не предполагается. Неизвестная группа не расширяет форму.

Макет использует существующую палитру, карточки и спокойные переходы. В нём
демонстрационные данные и схематичные изображения; он не подключён к БД.
Перенос дневника в корневую навигацию требует отдельной доработки Diary_VM:
сейчас диапазон дат и доступ к дневнику зависят от программы. Эта новая
структура пока является предложением, а не описанием внесённых QML-изменений.

Принципы: сохранять контекст и состояние разделов, явно обозначать принадлежность
данных, раскрывать настройки по запросу и не создавать конкурирующие назначения.
Источники: [Apple — Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars),
[Apple — Layout](https://developer.apple.com/design/human-interface-guidelines/layout),
[Apple — Scroll views](https://developer.apple.com/design/human-interface-guidelines/scroll-views).
