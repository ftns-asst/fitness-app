# Референсный UI-дизайн

Скриншоты экранов из прототипа дизайнера (`fitness-assistant-prototype.html`).
Это источник истины по визуальному оформлению: при расхождении с описаниями
`docs/fitness-assistant-frontend-design.md` приоритет у скриншотов.
Логический размер экрана — 390×812, светлая тема, акцент по умолчанию — синий.

## Уточнения референса поверх `.mk`-документа

1. **Сегодня**: строки даты нет; бейджи hero — одна акцентная строка
   «Full body · новичок»; сводка «5 упражнений · около 55 минут» полужирная;
   номер недели справа крупным акцентным числом; вес упражнения в списке —
   приглушённый caption; кнопки «Другой план» / «История» равноширинные;
   внизу карточка «Личный рекорд».
2. **Планы**: promo-карточка «Не знаете, что выбрать?» с компактной CTA
   «Подобрать»; сортировка — chips-ряд («По рейтингу», «Популярные»,
   «По времени»), а не segmented control; у карточки плана rating-pill «★ 4,7»
   справа сверху, число отзывов — серый tag; кнопка «Подробнее» отсутствует,
   карточка кликабельна целиком.
3. **Упражнения**: поиск и accent-кнопка «+ Своё» в одной строке; строки
   каталога — отдельные карточки с квадратным плейсхолдером «фото техники»
   и шевроном; отдельной нижней кнопки добавления нет.
4. **Профиль · Прогресс**: первая KPI-карточка tinted-accent, подпись и дельта
   акцентным цветом (не зелёным); остальные — серые tiles без border и тени;
   heatmap — 2 ряда по 12 недель, 4 уровня насыщенности, легенда
   «реже → чаще» и подпись «0–3 тренировки в неделю»; личные рекорды — список
   «название · значение жирным · дата».
5. **Навигация**: detail-страницы (карточка плана, карточка упражнения)
   сохраняют tab bar; отзыв на план, запись тренировки и таймер отдыха —
   вне вкладок, tab bar скрыт.
6. **Status bar**: во время записи тренировки слева вместо времени —
   «офлайн» акцентным цветом.
7. **Запись тренировки**: вес — перетаскиваемая линейка с шагом 2,5 кг
   (метки каждые 10 кг, текущее деление акцентное); повторы — бесконечное
   колесо, выбранное значение в accent-рамке, ввод до 10 000; RPE 5–10 —
   круглые кнопки, выбранная — accent fill; заметка к подходу — раскрывающийся
   textarea; цель — записать подход не более чем за 3 касания.

## Проверка вёрстки и адаптивности

Десктоп-запуск поддерживает флаги дизайн-ревью:

| Флаг | Назначение |
|---|---|
| `--frame` | окно-рамка 390×812 (§6.3) |
| `--tab <0..3>` | стартовая вкладка |
| `--dark`, `--accent <0..3>` | тема и акцент |
| `--width <px>`, `--height <px>` | размер окна: проверка узких 360 dp и широких окон |
| `--screenshot <путь.png>` | снимок контента и выход (ревью/CI) |
| `--diag` | аудит вёрстки: печатает в stderr `TEXT-WIDTH`/`TEXT-HEIGHT` (текст не влезает в элемент), `OVERFLOW-X` (элемент вылезает за родителя), `ZERO-WIDTH` (схлопнутый элемент) и завершает приложение |

Аудит требует `QT_FORCE_STDERR_LOGGING=1`:

```powershell
$env:QT_FORCE_STDERR_LOGGING = '1'
.\appTrainingAppClient.exe --diag --width 360 --height 780 --tab 2
```

Норматив: `problems=0` на всех четырёх вкладках при 360, 390 и 480 px,
в framed-режиме и в тёмной теме. Внутренности `MultiEffect` (auto-padding тени)
и контент прокручиваемых `Flickable` (ряд chips) аудит не проверяет — их
выход за границы штатный.

На широком окне контент не растягивается: он ограничен `Theme.contentMaxWidth`
(480 px) и центрируется, поэтому карточки и графики сохраняют телефонные
пропорции.
