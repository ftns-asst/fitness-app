# Код-стайл C++ — AStyle (UE) в адаптации для Qt

## 0. Источник и область применения

- Основание: документ **«Кодстайл AStyle»**,
  При расхождении данного файла
  и исходного документа приоритет у исходного, кроме явно перечисленных
  Qt-адаптаций (§1).
- Применяется ко всему C++ коду проекта: `src/`, `tests/`, `main.cpp`.
- Не применяется к: QML/JS-файлам (там — конвенции Qt QML: lowerCamelCase,
  4 пробела, id-первая строка), CMake-файлам, стороннему коду.
- Автоформатирование: `.clang-format` в корне репозитория (см. §10). Всё, что
  clang-format не контролирует (имена, префиксы, разделители, языковые
  запреты), проверяется на код-ревью.

## 1. Решения по адаптации к Qt (исключения)

Принятое допущение: Qt — «движок» данного проекта, но в отличие от UE он не
требует собственных префиксов типов, поэтому префиксы AStyle сохраняются
для всех классов проекта, включая наследников QObject.

| # | Правило AStyle | Адаптация для Qt | Основание |
|---|---|---|---|
| 1 | Не-локальные имена `Words_With_Underscores` | Сигналы, слоты, `Q_PROPERTY`, `Q_INVOKABLE` — **lowerCamelCase** | Имена видны из QML; биндинги регистрозависимы. AStyle 2.4.3: «имена из других языков сохраняют написание» |
| 2 | Макросы не определять | Макросы Qt (`Q_OBJECT`, `QML_ELEMENT`, `QML_SINGLETON`, `Q_PROPERTY`, `emit`) используются как есть | Требование фреймворка |
| 3 | Лямбды запрещены (12.4) | Разрешены **только** в `QObject::connect` и колбэках `QNetworkAccessManager`/`QtConcurrent`; тело — минимальное (1–5 строк); альтернатива — указатель на метод (PMF) или приватный слот | Исключение «когда этого ожидает движок» по аналогии с UE |
| 4 | Классы — префикс `A` | QObject-наследники (ViewModel, сервисы) — тоже `A`; сервисы-синглтоны — `As` (`AsRest_Timer`) | Qt специальных префиксов не требует |
| 5 | Интерфейсы избегать (1.2) | Абстрактные классы репозиториев допускаются (подмена в тестах); префикс `A`, без `I` (`AExercise_Repository`) | AStyle префикс `I` не определяет |
| 6 | Указатели — `0`, не `nullptr` (9.4) | В нашем коде — `0`; в сигнатурах, переопределяющих виртуальные методы Qt, — как в базовом классе | Совместимость с API |
| 7 | Касты только C-style (8.3) | `static_cast` допустим, только если C-style не компилируется (отдельные шаблоны/enum-контексты Qt) | Минимальное отступление |
| 8 | Умные указатели не использовать (14.2) | Время жизни объектов — родитель-потомок QObject; владение фиксируется в коде комментарием | Qt-механизм владения |
| 9 | STL-контейнеры инкапсулировать (13.2) | Используются Qt-контейнеры: `QString`, `QVector`, `QHash`, `QList` | Аналог UE-контейнеров |
| 10 | Без исключений, ассертов, `constexpr`, `typedef/using`-алиасов | Без изменений; ошибки — через коды возврата и `Last_Error()`, проверка инвариантов — логирование + `//!!!` | 11.4, 14.4, 12.3, 8.6 |

## 2. Имена

Термины: **локальное имя** — объявленное внутри функции (параметр, переменная,
константа, метка); **не-локальное** — всё остальное.

- Слова в именах разделяются `_`; имя не начинается и не заканчивается `_`
  (кроме меток); число — отдельное слово (`Method_1`).
- Двойное подчёркивание `__` — временно допустимо, требует рефакторинга.
- **Локальные имена**: все слова строчными: `file_path`, `first_pos`, `i`.
- **Не-локальные имена**: все слова с заглавной: `Open()`, `Last_Error`,
  `Parse_XML_Tag()`.
- **Аббревиатуры**: локальные — строчными (`xml_tag_name`), не-локальные —
  КАПСОМ (`Convert_XML_To_JSON()`, `HTTP_Packet`).
- **Префиксы** (1–2 символа, слитно с именем, без `_`):

| Сущность | Префикс | Пример |
|---|---|---|
| Класс (включая QObject-наследников) | `A` | `ASql_Database`, `AWorkout_Logger` |
| Класс-синглтон (единственный экземпляр) | `As` | `AsRest_Timer`, `AsNetwork_Monitor` |
| Структура | `S` | `SSync_Change`, `SWorkout_Set` |
| Перечисление | `E` | `EMuscle_Group`, `ESync_Op` |
| Объединение | `U` | `UFile_Time` |

- **Перечисления**: `enum class` с явным размером; константы без префиксов:

```cpp
enum class ESync_Op : unsigned char
{
	Insert,
	Update,
	Delete
};
```

- **Булевы имена**: не-локальные — `Is_Dirty`, `Has_More` (слова-признаки);
  локальные — `is_ready`. Префикс `b` не используется.
- **Метки**: начинаются с `_`: `_error_exit:`.
- **Макросы**: КАПС через `_`; новые не определяем (только условная компиляция
  кросс-платформенных участков).
- **Поля классов и структур** — не-локальные имена: слова с заглавной буквы,
  **без сокращений**: `QSqlDatabase Sql_Database;`, `QString File_Path;`,
  `bool Is_Open;` (не `db`, `file_path`, `is_open`). Это же относится к
  статическим переменным в `.cpp` (`Connection_Counter`).
  При коллизии имени поля с именем метода (`Last_Error()`) поле получает
  уточняющее слово: `Last_Error_Text`, `Current_Schema_Version`.
- **Принадлежность**: без `m_` и без хвостового `_` — принадлежность видна
  из секции класса.
- **Файлы и каталоги**: синтаксис не-локальных имён: `Sql_Database.h`,
  `Workout_Logger.cpp`; каталоги — `Data`, `Domain`, `Presentation`.
  Имена файлов/каталогов, приведённые в `01-architecture.md` §3, были намечены
  до принятия AStyle и являются логической структурой; при реализации Этапа 1+
  приоритет имеет именование по настоящему документу
  (например: `src/Data/Local/Sql_Database.h`, `src/Domain/Services/Workout_Logger.h`).

## 3. Файлы и #include

- Первая строка заголовка — `#pragma once` (header guard запрещён).
- Кодировка файлов — UTF-8 with BOM (Codepage 65001).
- Подключаются только `.h`; `.cpp` не подключать; precompiled headers не
  использовать.
- Совместно используемые типы (класс + его перечисления, одна иерархия) —
  в одной паре `.h/.cpp`; не создавать файл на каждый enum.
- `#include` — полный путь от корня `src/` в кавычках: `#include "Data/Local/Sql_Database.h"`;
  системные/Qt — в угловых. В `.cpp` — минимум подключений: иерархия
  заголовков выражает иерархию сущностей (подключённый `.h` самодостаточен,
  forward declarations — признак неправильно собранного заголовка).
- В одном `.h/.cpp` — один основной тип (плюс тесно связанные вспомогательные).

## 4. Структура кода

### 4.1. Класс
- Секции объявляются по одному разу, порядок: `public`, `protected`, `private`.
- Порядок членов внутри секции:
  1. деструктор и конструкторы;
  2. виртуальные методы;
  3. операторы;
  4. не-статические методы;
  5. не-статические данные;
  6. статические методы;
  7. статические данные.
- Члены класса не изолируются без нужды: `const` — минимум (только где его
  отсутствие меняет смысл), геттеры/сеттеры не плодить ради инкапсуляции
  (AStyle 1.2).

### 4.2. Конструктор
- Инициализация пользовательских типов — в списке инициализации; встроенных —
  в описании класса (§7.2).
- Длинный список инициализации можно переносить по одному параметру на строку.

### 4.3. Методы и глобальные функции
- В заголовке — объявление (с однострочным описанием-комментарием, если имя
  недостаточно говорящее); в `.cpp` — определение.
- Inline-функции в заголовке — только тривиальные (1–3 строки, без логики);
  остальное — в `.cpp`.
- Глобальные функции — только если не относятся ни к одному типу; иначе
  статический метод класса.

### 4.4. Наследование и friends
- Наследование — от одного базового типа; множественное — только интерфейсное
  (в нашем случае — абстрактные классы репозиториев, §1 п.5).
- `friend` — не использовать; при необходимости — пересмотреть архитектуру.

### 4.5. Порядок определений в .cpp
- Все функции одного класса — одним блоком, в порядке объявления в классе.
- Если в файле несколько классов: перед блоком — комментарий `// AClass_Name`,
  между блоками — 4 пустые строки.

## 5. Форматирование

- Отступ — один таб (не пробелы!); выравнивание продолжений строк — пробелами
  до позиции первого аргумента (`AlignAfterOpenBracket: Align`).
- Скобки — Allman: каждая `{` на отдельной строке; тело — с новой строки.
- Однооператорные `if/for/while` — без скобок, тело с новой строки с отступом:

```cpp
if (is_red)
	Do_Something();
else
	Do_Nothing();
```

- `else` — на новой строке (не `} else {`).
- `switch/case`: `case` на уровне `switch`, код case — с новой строки:

```cpp
switch (state)
{
case ESync_Op::Insert:
	Do_Insert();
	break;  // No break! — если проваливаемся намеренно (комментарий обязателен)

default:
	Do_Default();
	break;
}
```

- `return` без скобок: `return value;`.
- `&` и `*` — часть имени: `int *ptr`, `const QString &name` (не `int* ptr`).
- Перенос длинных условий — перед `||`/`&&`, продолжение выравнивается:

```cpp
if ( (symbol >= 'a' && symbol <= 'z')  ||  (symbol >= 'A' && symbol <= 'Z')
   ||  (symbol >= 'а' && symbol <= 'я')  ||  (symbol >= 'А' && symbol <= 'Я'))
	return true;
```

- Логические секции кода отделяются пустыми строками; перед `return` — пустая
  строка (если перед ним была другая секция).
- Ширина строки — 120 символов (`.clang-format ColumnLimit`).

## 6. Комментарии

- Формат: `// ` + текст с заглавной буквы; комментарий в конце строки — через
  два пробела: `Init();  // Инициализация программы`.
- **Длинный разделитель** — строка из 75 символов `//---…---`:
  - разделяет все описания типов в файле;
  - ставится перед первым и после последнего определения функции в `.cpp`;
  - в заголовке — между логическими блоками объявлений.
- **Комментарий области видимости** — сразу после `{`, описывает алгоритм:

```cpp
if (is_red)
{// Если объект красный — используем уже установленный цвет фона.
 // При этом цвет текста заменяем на белый.
	...
}
```

- **Описание функции** (если имени недостаточно):

```cpp
//---------------------------------------------------------------------------
// Возврат: true, если подход записан; false — ошибка (см. Last_Error()).
// Параметры: set_id — UUID подхода; weight_kg — рабочий вес.
//---------------------------------------------------------------------------
```

- Специальные комментарии: `//!!!` — отсутствует логика (вместо assert),
  `// No break!` — намеренное проваливание в switch, `// UNO` — временное
  решение одного разработчика, требующее проверки.
- Комментарии — на русском (допускается английский для устоявшихся терминов).

## 7. Типы, инициализация, проверки

### 7.1. Типы
- Встроенные типы вместо `<stdint.h>`: `char`, `unsigned char`, `short`, `int`,
  `unsigned int`, `long long`, `float`, `double`.
- Без RTTI (`dynamic_cast` запрещён); полиморфизм — виртуальные функции.
- Преобразования — только C-style: `int a = (int)12.3f;`; `static_cast` —
  крайняя (§1 п.7), `dynamic_cast/const_cast/reinterpret_cast` — запрещены.
- Без `typedef`/`using`-алиасов; `auto` — только как тип итератора в
  range-based for по контейнерам.
- `enum class` с явным размером (§2).
- В контейнерах хранить указатели на объекты, не экземпляры (кроме POD-структур
  данных — `SWorkout_Set` и т.п., где экземпляр эффективнее).

### 7.2. Инициализация
- Встроенные типы — только присваиванием: `int count = 0;`.
- Сложные типы — только в круглых скобках: `ASql_Database db(file_path);`.
- Фигурные скобки — только для массивов и чужих POD-типов.
- Указатели — `0` (не `nullptr`, не `NULL`): `float *ptr = 0;`.
- Все не-статические члены встроенных типов инициализируются **в описании
  класса**; пользовательских типов — в списке инициализации конструктора.

### 7.3. Проверки значений
- bool — проверять значение: `if (is_red)` (не `== true/false`).
- Всё остальное — явное условие: `if (ptr != 0)` (не `if (ptr)`, не `!!ptr`).
- Отсутствие объекта — возвратом `false` + выходной параметр, не нулевым
  указателем:

```cpp
bool Get_Active_Session(SWorkout_Session &out_session);
```

- Тернарный оператор — только для коротких выражений; развёрнутые условия
  предпочтительнее компактных.


## 8. Особенности C++

- `this` — использовать только при неоднозначности (параметр совпал с именем
  члена); в остальных случаях — не писать.
- `goto` — только для единой точки выхода с ошибкой внутри одной функции
  (метка `_error_exit`); для циклов — запрещено:

```cpp
bool AExample::Do_Work(int param_1, int param_2)
{
	if (!Check_Param(param_1))
		goto _error_exit;

	Do_Cool_Stuff(param_1);
	Do_Something_Else(param_2);

	return true;

_error_exit:
	Log_Error("Can't perform example for", param_1, param_2);
	Make_Some_Finalization();

	return false;
}
```

- Макросы — только условная компиляция (`#ifdef Q_OS_ANDROID`); динамическое
  построение идентификаторов макросами запрещено. Альтернатива — статические
  методы и шаблоны.
- Исключения — не использовать для управления потоком; допустимы только как
  «аварийный стоп» при отладке (std::runtime_error с сообщением). Ошибки —
  коды возврата + `Last_Error()`.
- Шаблоны — использовать умеренно: только когда тип действительно обобщается
  (например, `AResult<T>` для возврата значения/ошибки); без метапрограммирования.
- Без `constexpr`; константы — `const` переменные/члены, вычисляемые явно.

## 9. Стандартная библиотека и контейнеры (адаптация для Qt)

- `std::cin/cout/cerr` — запрещены; вывод — через Qt-логирование
  (`qWarning()`/`qCritical()` + лог-категории).
- Контейнеры: в проекте — **Qt-контейнеры** (`QString`, `QVector`, `QHash`,
  `QList`, `QByteArray`); STL-контейнеры — только внутри инкапсулирующих
  классов, если Qt-эквивалента нет.
- Алгоритмы STL — избегать: операции инкапсулируются в методы контейнера или
  объекта (`AList::Sort()`-подход). Простые циклы — обычный `for` с индексом
  или range-based for.
- Умные указатели (`std::shared_ptr`, `QSharedPointer`) — не использовать;
  владение — иерархия QObject (родитель удаляет потомков) либо явный
  единственный владелец (комментарий о владении обязателен).
- Boost — запрещён.
- Ассерты — запрещены; вместо них — логирование + `//!!!`.
- Сериализация — алгоритмическая (чтение/запись полей кодом), не отображение
  на POD-структуру.

## 10. Инструменты: clang-format и код-ревью

### 10.1. `.clang-format` (корень репозитория)
Автоматизирует раскладку текста: табы (ширина 4), Allman, `AccessModifierOffset: -4`
(секции на уровне скобки класса), `PointerAlignment: Right` (`int *ptr`),
`ColumnLimit: 120`, переносы аргументов/условий, `AllowShort*: None/Never`.

**Не автоматизируется** (проверяется на ревью, чек-лист):
- префиксы и регистр имён (`A`/`As`/`S`/`E`/`U`, `Words_With_Underscores`,
  локальные `lower_case`);
- комментарии-разделители `//----…----` (75 символов);
- запреты: `nullptr`, `static_cast`-семейство, лямбды вне connect, исключения,
  ассерты, умные указатели, `typedef/using`, `constexpr`, STL-потоки;
- порядок членов класса (§4.1), инициализация в описании класса (§7.2);
- `#pragma once`, UTF-8 BOM, иерархия include.

Запуск: `clang-format -i src/**/*.cpp src/**/*.h` (или формат-при-сохранении
в VS Code: `editor.formatOnSave` + расширение clang-format). Проверка в CI:
`clang-format --dry-run --Werror`.

### 10.2. clang-tidy (опционально, пост-MVP)
Для частичной автоматизации запретов возможен `.clang-tidy` с включёнными
`bugprone-*`, `readability-identifier-naming` (кастомные регистры под AStyle)
и **отключёнными** `modernize-use-nullptr`, `modernize-use-auto`,
`cppcoreguidelines-*` (противоречат AStyle). В Этапе 1 не вводится — чтобы не
конфликтовать с Qt-макросами до стабилизации кодовой базы.

### 10.3. VS Code
`.clang-format` в корне подхватывается расширением clang-format / C++ Tools
автоматически; для проекта достаточно `"[cpp]": { "editor.formatOnSave": true }`
в настройках workspace.

## 11. Сводный пример

```cpp
#pragma once

#include <QSqlDatabase>
#include <QString>

//---------------------------------------------------------------------------
enum class EDb_State : unsigned char
{
	Closed,
	Open,
	Error
};
//---------------------------------------------------------------------------
// Класс единственной локальной базы данных приложения (синглтон по смыслу).
//---------------------------------------------------------------------------
class AsSql_Database
{
public:
	AsSql_Database(const QString &in_file_path);
	~AsSql_Database();

	bool Open();
	bool Migrate();
	int Seed_All();  // Возврат: число вставленных строк, -1 при ошибке

	QSqlDatabase &Get_Qt_Database();
	QString Last_Error() const;

private:
	QSqlDatabase Sql_Database;
	EDb_State State = EDb_State::Closed;
	QString File_Path;
	QString Last_Error_Text;  // коллизия с методом Last_Error() — уточняющее слово
	int Current_Schema_Version = 0;
};
//---------------------------------------------------------------------------
```

```cpp
#include "Data/Local/Sql_Database.h"

#include <QDir>
#include <QFile>
#include <QSqlError>
#include <QSqlQuery>
#include <QTextStream>

//---------------------------------------------------------------------------
// AsSql_Database
//---------------------------------------------------------------------------
AsSql_Database::AsSql_Database(const QString &in_file_path)
	: File_Path(in_file_path)
{
}
//---------------------------------------------------------------------------
bool AsSql_Database::Open()
{
	QDir dir;

	dir.mkpath(QFileInfo(File_Path).absolutePath());
	Sql_Database = QSqlDatabase::addDatabase("QSQLITE", "training_db");
	Sql_Database.setDatabaseName(File_Path);

	if (!Sql_Database.open())
	{
		Last_Error_Text = Sql_Database.lastError().text();

		return false;
	}

	State = EDb_State::Open;

	return true;
}
//---------------------------------------------------------------------------
```

Примечания к примеру:
- параметр конструктора `in_file_path` — локальное имя (строчное), инициализация
  поля `File_Path` в списке инициализации;
- поля класса — не-локальные имена без сокращений: `Sql_Database`, `File_Path`,
  `Is_Open`; при коллизии с методом — уточняющее слово (`Last_Error_Text`);
- локальная переменная `dir` объявлена в начале функции до кода (§5.2 исходного
  документа);
- `Sql_Database.open()` — bool, проверка без `== true`; ошибка — `return false` +
  `Last_Error_Text`, без исключений;
- определения разделены длинными разделителями, перед первым блоком — комментарий
  с именем класса.
